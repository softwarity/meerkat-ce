Reason @for (r of reasons; track r.key) { {{ r.label }} } How long @for (d of durations; track d.key) { {{ d.label }} }

Optional, and an estimate rather than an appointment. The page keeps the size of what you chose - a day announced still reads as a day an hour later - and only says something smaller once what is left really is smaller. It never repeats it to the minute: a promise to the minute is one a window famously breaks. Left empty, the page says service will be back shortly rather than leaving a blank; an outage with no horizon reads as an abandoned service.

timer
How long to wait for a service

The first is the time to establish the connection - a service that is not listening, a closed port, a network swallowing packets. The second starts once the request is sent and bounds the wait for the answer's first line: the service is thinking. Past either, the caller gets a 502 instead of waiting. What follows the first line is never bounded: a download or a websocket runs as long as it needs.

memory
Body rewriting ceiling

Filters that change a response body - injecting, removing JSON fields - have to hold it in memory to do it. Past this size the answer is forwarded untouched instead: nothing breaks, the filter simply does not apply. The cost is per request being served at that moment, so a large ceiling multiplies by however many arrive together.
