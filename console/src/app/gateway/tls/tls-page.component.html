HTTPS on a local machine

A laptop or a lab has no public name and no public authority. Give the names an address, make an authority this machine's browsers trust, have it sign one certificate for them all, import it here and place it.

macOS Linux Windows

  1. Point the names at the gateway in the hosts file. 127.0.0.1 when it runs on this machine (Docker, a local Kubernetes); its address otherwise - a VM, minikube, another machine. localhost needs no line.

  2. Create a local authority with mkcert, and make this machine trust it: the system store, Chrome, Edge, Safari, and Firefox through nss. Restart the browsers afterwards.

    Its private key stays in the folder mkcert -CAROOT prints: whoever holds it can sign for any name this machine will believe. Never share it; another machine makes its own.

  3. Sign one certificate for every name of step 1: a meerkat.pem and its meerkat-key.pem, in the current folder.

  4. Import it here: Add certificate on Console, Import a PEM pair, and drop the two files on the dialog; then the same on Application.

Browsers keep the port: the HTTPS address is the one the links on this screen show, not 443, unless the gateway is published there.
