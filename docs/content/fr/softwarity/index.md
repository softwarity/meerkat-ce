# Softwarity

Softwarity écrit du logiciel pour ceux qui écrivent du logiciel dans les
entreprises. Pas des applications grand public, pas des API publiques : les
**applications internes** qu'une DSI porte - celles qui ont de vrais
utilisateurs, de vraies données, de vraies règles d'accès, et une petite équipe
derrière.

Ces équipes finissent toutes par écrire les mêmes choses. Une page de connexion.
Un modèle de rôles. Une table d'utilisateurs. Un journal d'audit que quelqu'un a
réclamé après un incident. Une configuration de gateway que personne n'ose
toucher un vendredi. Ce travail est nécessaire, il n'est jamais le sujet, et
c'est là que passent les semaines.

::: lead
Notre réponse est de sortir cette moitié de l'application et de la mettre là où
elle a sa place : devant. C'est ce qu'est [Meerkat](/index), et c'est la forme
de tout ce que nous faisons : la part répétitive devient un produit, pour que la
part qui est la vôtre le reste.
:::

## Ce que nous faisons

::: cards
### Des produits

[Meerkat](/index), l'app-gateway : une porte devant une application interne,
qui prend en charge l'authentification, les règles d'accès, les organisations,
le routage, les quotas et l'audit. Son ancêtre, **Archway**, faisait le même
travail sur une pile Spring Cloud Gateway. Il nous a appris quoi faire
autrement, et jusqu'où l'idée pouvait aller.

### Des outils

[plug](https://github.com/softwarity/plug) met le poste d'un développeur à
l'intérieur d'un cluster : un service qui tourne sur un portable répond sous son
nom de cluster, et tout le reste continue comme avant.

### De l'open source

Une étagère de composants Angular dont nous avions besoin, publiés plutôt que
recopiés de projet en projet : rails de navigation, actions de ligne,
indicateurs de chargement, sélecteurs de fuseau horaire. Voir
[Open source](/softwarity/open-source).
:::

## Ce sur quoi vous pouvez compter

Mettre une passerelle devant ses applications est un engagement long. Voici ce
que cela vous rapporte de notre côté.

**Vous pouvez vérifier le produit avant de lui faire confiance.** Ce qui est
construit et ce qui ne l'est pas tient dans un tableau du dépôt, lu dans le
code et non dans un plan. Rien sur ce site n'annonce « bientôt » à propos de
quelque chose qui n'existe pas.

**Vous n'êtes pas enfermés.** Le cœur est à sources ouvertes et devient de
l'Apache 2.0 sans condition deux ans après chaque version : ce que vous
déployez aujourd'hui ne peut pas vous être repris. Toute votre configuration
s'exporte en un fichier que vous pouvez lire et rejouer ailleurs. Et la
passerelle ne nous envoie jamais rien : il n'y a aucune télémétrie dedans.

**Quand quelque chose ne va pas, vous joignez ceux qui l'ont écrit.** Il n'y a
pas de palier de support entre vous et le code.
